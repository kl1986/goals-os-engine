# Project tracking v1: `## Next action` and task-bearing `## Backlog` dropped — tickets are the sole store of a Project's open work

`project-tracking.md` v0 gave every Project note its own `## Next action` (checkbox list) and `## Backlog` sections, in parallel with the `tasks/projects/<slug>/` ticket system ADR-0012 established for Goals OS's own dev work. In practice this produced exactly the "separate task management places" split goals-os-27 flagged — e.g. `[[Clear the garage]]` carried 5 live checkbox items in `## Next action` while its `tasks/projects/clear-the-garage/` folder sat empty. Decided 22/07/2026: `## Next action` is removed from the schema entirely; every Project's and Area's open work lives only as tickets. `## Backlog` stays, but is redefined as free-text notes on future phases/ideas (not a checkbox task list) — see `CONTEXT.md`'s disambiguation of "Backlog" (section) vs. `backlog` (ticket status).

**Rejected:** keeping Next action/Backlog as an opt-in lightweight tier for small Projects, with tickets reserved for Goals OS's own dev work — rejected because it leaves the same two-store problem in place for every Project that opts out, just narrower.

**Consequences:** existing Next-action lines migrate one-for-one into tickets (`status: prioritised`, one file per line, in existing order) via a one-time script, then the section is deleted from each Project note. `planning-session.md`'s Area-agent decomposition step now creates tickets directly rather than appending Next-action lines. `daily-note.md`'s sourcing logic (ADR-0018) and `docs/agents/issue-tracker.md` both change downstream of this.
