# Ticket normalization Routine backfills Base Board quick-add cards; unmappable ones quarantine into `tasks/_unfiled/`

Base Board's card-creation flow (`createNewCard` in `main.js`) only ever sets the two properties intrinsic to the board itself — `status` and `kanban_order` — before creating the file; it has no awareness of the ADR-0015 ticket schema or the `<slug>-<number>-<desc>` naming convention (ADR-0014), and the plugin exposes no template/schema config to teach it one. Confirmed in the wild: `tasks/projects/return-on-constraints/bye.md` and `return-on-constraints-1.md`, both quick-added with only `status:`/`kanban_order:`, no title, no body, non-conforming filenames. Decided 22/07/2026: a new daily, heartbeat-checkable Routine (owner EA, risk tier internal & reversible) scans `tasks/**/*.md` for files missing any ADR-0015 frontmatter key, backfills what it safely can (blank fields, `type: task` as default), and renames/re-IDs the file using its parent folder's slug (`tasks/projects/<slug>/` or `tasks/areas/<slug>/` tells you the slug) plus the next free number for that slug.

A card can land with no inferable slug at all — e.g. quick-added from `all-tickets.base`'s "All" view (`file.inFolder("tasks")`, spanning every folder), which may drop the file directly under `tasks/` with no per-slug subfolder. For that case, the Routine moves the file into a new `tasks/_unfiled/` holding folder rather than leaving it in place or guessing a slug. This extends ADR-0012's `tasks/projects/<slug>/` + `tasks/areas/<slug>/` layout with a third, deliberately-not-slug-scoped location.

**Rejected:** leaving unmappable cards in place with just an Action Log entry (the lower-friction option) — rejected in favour of quarantining, to make the batch of "needs manual re-filing" cards trivially visible as a folder listing rather than something you'd only notice by reading the Action Log.

**Rejected:** treating this as a process/discipline fix ("always use the Publish skill, never quick-add") — rejected because it doesn't actually fix anything for a human using the board's own UI, which is the whole point of having a drag-and-drop board.
