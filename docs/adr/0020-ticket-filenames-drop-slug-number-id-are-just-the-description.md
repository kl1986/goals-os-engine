# Ticket filenames drop the slug-number ID; a ticket is identified by its description, cross-referenced by wikilink

ADR-0014 gave every ticket a `<slug>-<number>` ID (e.g. `epoch-fit-mvp-7`), filename `<slug>-<number>-<short-desc>.md`, reasoning this kept IDs "small and Jira-like." In practice this repeated the project/area name on every single ticket inside a folder that's already scoped to that project/area (`tasks/projects/<slug>/`) — the prefix carried no information the folder didn't already give, while making filenames longer and the number an arbitrary, meaningless-outside-context counter. Decided 22/07/2026: dropped.

**New identity:** a ticket has no separate ID field or number. Its filename is a slugified version of its own title (its H1) — lowercase, hyphenated, punctuation stripped — nothing else. Uniqueness comes from two things already true of the schema: the owning folder (`tasks/projects/<slug>/` or `tasks/areas/<slug>/`) scopes it, and a ticket's title is itself the description, so two tickets in the same folder needing the same filename is a genuine title collision, not a normal case — handled with a `-2`, `-3`... numeric suffix, exceptional rather than default.

**Long titles:** a ticket's title can be a full free-text sentence (e.g. a migrated Next-action line), which would slugify to an unwieldy 150+ character filename verbatim. Truncate to ~60 characters at the last word boundary before the limit. This is a length bound on the *filename*, not the title — the H1 in the ticket body is never truncated.

**Cross-references:** the `> Blocked by: <ticket-id>` body convention and a Subtask's `parent:` frontmatter field both previously held a bare `<slug>-<number>` string. Both now hold a `[[wikilink]]` to the ticket note directly — Obsidian already resolves wikilinks by filename everywhere else in the Brain; a ticket doesn't need a second, ID-shaped way to be referenced.

**Unchanged:** ADR-0012's folder-per-Project/Area filing (`tasks/projects/<slug>/`, `tasks/areas/<slug>/`), ADR-0015's frontmatter schema (`status`, `type`, etc. — none of these ever encoded the slug-number ID), and ADR-0019's ticket-normalization Routine's folder-slug-scoped quarantine logic (`tasks/_unfiled/` for files with no inferable folder) — only the *filename* identity changes, not where a ticket is filed or what its frontmatter holds.

**Consequences:** every existing ticket file is renamed in a one-time pass (`scripts/rename_tickets_drop_id_prefix.py`, same shape as the other one-time migration scripts) to `<slugified-title>.md`. The nine existing `> Blocked by: goals-os-N` references under `tasks/projects/goals-os/` are rewritten to `[[<new-filename>]]` in the same pass. `docs/agents/issue-tracker.md`, `CONTEXT.md`'s "Ticket ID" entry, `protocols/ticket-normalization.md`, and `scripts/ticket_normalization.py`/`scripts/migrate_next_actions.py` (and their tests) all change to stop minting/inferring slug-number IDs and instead derive a filename from the title alone.

**Rejected:** keeping a running number per folder purely for stable ordering (`description-1.md`, `description-2.md`) — rejected because ordering isn't actually needed (Base Board's own `kanban_order` already handles manual ordering; file-creation order is recoverable from git history if ever needed), and it reintroduces exactly the "meaningless counter" ADR-0014 is being walked back from.
