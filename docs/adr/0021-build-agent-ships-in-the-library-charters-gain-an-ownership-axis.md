# The build agent ships in the Library, and Charters gain an ownership axis

`/build` — the pipeline that takes a Batch of Tickets through to shippable, documented code — ships as a **Library plugin**, not as Engine core. Every Engine Protocol to date is about running a *life* (capture, triage, wiki, routines, project tracking); a software-engineering pipeline is opt-in, and it carries dependencies (git worktrees, third-party skills) the Engine's core surface has none of. A Brain owner who isn't a developer should never receive it. Decided 23/07/2026.

Its orchestrator, the **Foreman**, is a System agent — Capability agents are `directs: none` and so cannot spawn the Coder and Reviewer commissions a Build needs. But `charter-schema.md` v0 states that generic charters are "Engine-owned" and that System agents are "Engine singletons," which a Library-shipped System agent is not. The schema therefore goes to **v1 with a new `owner:` field (`engine | plugin`)**: Engine charters stay singletons (EA, Librarian, Coach); plugin charters are optional, namespaced by their plugin, and present only when that plugin is installed.

**Considered options.** *Engine core* — every install gets it and it may assume every Protocol is present, but it drags dev tooling and third-party skill dependencies into the shared core. *A fourth `charter-kind: plugin`* — perfectly firewalls the Engine's agent kinds, but adds a fourth kind to a taxonomy the Engine's `CONTEXT.md` deliberately fixed at three. *Library ships generic, Brain materialises an instance* — reuses existing generic→instance machinery, but System agents have never had instances, so it stretches a different part of the same schema. *Keep the charter in the Engine as a one-off exception* — no schema change at all, but the Engine would then define an agent most Brains can never use, which is exactly what Library placement was chosen to avoid.

**Consequences.** This is the first crack in the Engine/Library boundary drawn by ADR-0003 and ADR-0004: the Library is no longer only "standalone capabilities with no Protocol behind them to bind to," and `goals-os-library/README.md` must be amended to say so. Every future Library plugin now has a sanctioned route to shipping its own agent.
