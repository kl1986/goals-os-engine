# A Build gates at push, not at commit

A Build commits autonomously and stops at the push/PR boundary. This is not a new autonomy rule — it is `risk-tier-classification.md`'s existing decision procedure applied to build actions. A local commit on a throwaway worktree branch sends nothing, spends nothing, messages nobody, and a `git revert` is a complete, true undo: **`build-commit` is `internal & reversible`**. A push, PR or merge reaches an external system and lets other work start depending on it: **`build-push` and `build-merge` are `outward-facing / hard-to-reverse`**, and per ADR-0006 those never graduate on silence — explicit validation only. Both are registered in the Brain's `config/action-types.md`, and the Foreman stamps Action Log entries so ADR-0006's graduation engine can read them. Decided 23/07/2026.

This **reverses** the earlier `lead-orchestrator-prompt.md` design, which made a per-Ticket pre-commit human gate its single mandatory pause. That gate was placed by intuition rather than by the taxonomy, and it was self-defeating: dependent Tickets waited on *commit approval*, so a five-Ticket Batch stalled at the first Ticket the moment nobody was watching — defeating the entire purpose of handing work to a Build.

**Considered options.** *Keep the pre-commit gate* — nothing lands unseen, but no Batch is more unattended than its first pause. *Fully autonomous through PR* — truest fire-and-forget, but outward-facing work would then happen on silence, which ADR-0006 forbids. *A per-run `--gate` flag* — pragmatic, but makes autonomy something asserted per invocation rather than earned from evidence, which is precisely what the graduation engine exists to prevent.

**Consequences.** Independent corroboration that the boundary is in the right place: `protocols/charters/capability/coder.md` already reads "Builds, doesn't deploy — it writes the code but stops before pushing," written before this decision and arrived at separately. Wiring the Action Log also retires that prompt's stated deferral of it: the `actor` taxonomy was said to have no slot for these roles, but `Coder` and `Reviewer` charters already existed, so entries read `Coder (via Foreman)`.
