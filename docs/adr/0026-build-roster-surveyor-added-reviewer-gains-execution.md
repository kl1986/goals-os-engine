# Build roster: a Surveyor is added, and the Reviewer gains execution rights

A Build commissions three Capability agents — **Surveyor** (new), **Coder** and **Reviewer** (both rewritten). There is deliberately **no Architect**: on a Batch whose Tickets are already decided, decomposition adds cost without adding decisions, and the one recorded trial of that machinery burned ~437K sub-agent tokens against a single fully-specified ticket for no value. Revisit only if a Batch genuinely arrives undecomposed. Decided 23/07/2026.

**The Reviewer's `No execution capabilities` is removed.** It may now run the target repo's *declared* test, lint and build commands inside the worktree — not arbitrary shell, so a broken or hostile repo cannot turn a review into an exploit. The charter's real principle is preserved verbatim: it critiques, it never enacts the fix, and it still has no write access. The old boundary made independent QA meaningless — a Reviewer that cannot run the suite is only reading a diff, and the obvious alternative (let the Coder run the tests and have the Reviewer judge the report) has the Reviewer trusting the output of the very agent it is checking, so a Coder that quietly weakened a test passes unnoticed.

**The Surveyor** assesses and hardens Tickets before any code is written. It resolves only what *evidence* can settle — the repo's real state, the Project note, an attached Map, ADRs, `CONTEXT.md`, existing conventions — because those are facts discovered, not decisions made. Anything requiring a preference or a fresh trade-off it must not resolve. Hardening is expected to have happened already, by a human running a grilling session; Survey verifies rather than performs it. This is what finally satisfies the originating ticket's requirement that the agent "check the quality of the requirements", which was previously judged impossible because `wayfinder` and `grill-with-docs` are `disable-model-invocation: true` — a blocker that vanished once ADR-0024 chose to vendor them, since a vendored copy's frontmatter is ours to write.

**Survey runs once, across the whole Batch, before any spend.** Where Tickets are thin the Foreman returns a single consolidated prompt naming each one and its specific unanswered question, offering: grill now / harden from evidence / proceed with assumptions marked / quarantine and skip. Answered once, the rest of the run is genuinely unattended. **Unattended or unanswered defaults to quarantine**, so a scheduled Build can never invent scope. Per-ticket prompting was rejected for stopping the batch at unpredictable moments; a per-run flag was rejected because it forces the choice before anyone knows which Tickets are thin.

**Known limitation (recorded 26/07/2026) — the Claude Code Adapter cannot enforce "declared commands only."** The narrowing above is a charter-level boundary, not a runtime-level one. Claude Code has no per-agent permission scoping: subagent frontmatter supports `tools:` alone (no `permissions:`, `allowed-tools:` or `disallowed-tools:`), so the grant is all-or-nothing and `Bash` means arbitrary shell; and `permissions.allow` rules in `settings.json` are session/project-scoped, so an allowlist tight enough for the Reviewer would equally bind the Coder, which legitimately needs arbitrary shell. A `PreToolUse` hook could in principle gate each command, but only if its payload identifies the calling subagent — unverified, and a hook that cannot distinguish Reviewer from Coder either blocks the Coder or enforces nothing. `.claude/agents/reviewer.md` therefore grants `Bash` (never `Edit`/`Write`) and documents the gap, rather than leaving ADR-0026's grant inert or shipping a guard that only looks real. **The hostile-repo case named above is consequently only partly mitigated:** the Reviewer is instructed not to run undeclared commands, but nothing prevents it. Revisit if Claude Code gains per-agent permission scoping.

**Consequences.** The Coder charter is rewritten in the same pass: its scope widens from `Code/` to the repos declared under `code_root` (ADR-0022), its Brain-write exception becomes explicit and per-commission rather than standing (protecting `areas/` and `config/` from an ordinary commission), and "builds, doesn't deploy" sharpens into "commits, doesn't push" per ADR-0023 — a boundary that charter had already reached independently.
