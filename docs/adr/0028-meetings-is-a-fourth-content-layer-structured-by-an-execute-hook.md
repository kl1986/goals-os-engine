# `meetings/` is a fourth content layer, structured by an Execute hook

Triage is classify-only by construction (Principle 10), so a meeting transcript can't be structured where it's classified, and `execute.md` v1.2 explicitly forbids Execute gaining source-specific action types. Structuring therefore fires from the `meetings` source's own `execute_hook.py` in the Library — after Kelvin's tick on a Triage row, so the model only ever runs on a capture he has already confirmed — and writes a structured note into a new top-level `meetings/` folder shipped in the Brain Template. That folder is neither Wiki (machine-compiled, concept-organised, resynthesizable) nor Curated (human-authored): Kelvin hand-writes agenda notes in it and the hook augments them in place, making it a deliberate fourth, mixed human/machine layer. Decided 24/07/2026 (meeting-processing ticket 01).

**Consequences worth calling out:**

- `execute.py`'s hook contract gains `--destination`, so the hook honours the route Kelvin ticked rather than re-deriving it. Generic — Execute still knows nothing about meetings.
- The hook has full write access to curated files (`projects/`, `people/`), which contradicts `CONTEXT.md`'s original "only the user writes it" definition of the Curated layer. The definition is amended to match reality rather than left silently false; `version-control.md`'s daily git commits are what make a bad unsupervised write recoverable.
- Hooks are headless `subprocess.run(..., check=False)` calls, so nothing downstream can be confirm-first and failures are silent by design. Mitigated by: additive-only Person Hub writes against existing, unambiguously-resolved hubs (anything needing judgment is written into the note as a proposal instead); a failed run appending an Action Log entry rather than relying on stderr; and a meeting/not-meeting fail-safe to `meetings/`, so an unsure guess lands in one reversible folder rather than scattering into `projects/`.
- Agenda augmentation is gated on an explicit `type: meeting-agenda` frontmatter marker, not v1's heuristic signal-sniffing — a headless model must never fuzzy-match its way into rewriting a note Kelvin authored.
- Solo dictation leaves this pipeline entirely and gets its own `source` (per ADR-0011's own advice), which is what dissolves the 50/50 meeting-vs-not problem in the live corpus.

**Rejected:** an Execute action type with a verb destination (cleanest fit with Principle 10 and graduation, but a Claude session structuring a 14,000-character transcript spends what ADR-0011's "genuinely different downstream treatment" and PRD Principle 7 both argue against); a dedicated Routine skipping Triage (removes the only human gate on a source whose captures write to curated files); a promoted Engine protocol (fights the hook decision — hooks are a Library extension point by construction); decomposing with no note at all, so decisions went to Project logs, actions to tickets, knowledge to the Wiki and nothing survived as a readable narrative (architecturally purest, and the reason v2's layout had no meetings folder, but it discards the synthesis Kelvin actually reads); per-Project meeting folders (no home for a 1-1 or a cold call, and "all my meetings" stops being a folder).
