# Triage Rows are task-list items, grouped by destination, and the Row line is authoritative

A Triage Plan renders its Rows as markdown task-list items (`- [ ] …`) under `## <destination>` headings, rather than as rows of a single markdown table. Each Row still carries its own destination on its own line; the heading it sits under is presentation. Where the two disagree, the Row line wins and Execute refuses the Plan rather than guessing. Decided 27/07/2026.

**Why:** Obsidian only renders task syntax as an interactive checkbox in list items — never inside a table cell. Approving a Row therefore meant hand-editing a space into an `x` inside a table cell, which on mobile is precise cursor placement in a horizontally-scrolling row. Approval is the one gesture the confirm-first design requires on *every* Row (see Approve, CONTEXT.md), so making it the most expensive gesture in the system was backwards. Grouping by destination follows from the same reasoning: the dominant real-world case is a large run of Rows sharing one destination (85 of 109 pending Rows were email, mostly discards), and grouping puts them under one heading to be approved together.

Keeping the destination on the Row line is what bounds the change. It leaves Row parsing *line-local* — one line is independently meaningful — so consumers that read Rows without caring about layout (the pending-work nudge, the Dashboard's ticked/pending counts) keep working untouched, and re-routing a capture stays an in-place text edit rather than moving a line between sections. A stateful, heading-driven parse would have propagated document structure into every consumer and made correction *harder* on the device this change exists to serve.

**Rejected:** grouping by route (Pass A/Pass B) — stable and churn-free, but it groups by *how* a Row was classified rather than by what the user is about to approve, so it doesn't enable bulk approval; heading-authoritative destinations (removes the duplication, but makes parsing stateful and re-routing a line-move); parsing both the old table and the new shape indefinitely (permanently doubles the surface that the shared parser exists to keep from drifting — the open Plans are converted once instead); leaving the table and adding conversational approval instead (cheaper, but doesn't fix the Plan for anyone reading it in Obsidian).
