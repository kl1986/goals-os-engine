# Triage Rows are task-list items, grouped by destination, and the Row line is authoritative

A Triage Plan renders its Rows as markdown task-list items (`- [ ] …`) under `## <destination>` headings, rather than as rows of a single markdown table. Each Row carries its own destination on its own line, and that line is the only thing anything reads. The heading is **regenerated output**: it is derived from the destinations of the Rows beneath it on every write, and is never compared to anything. Decided 27/07/2026.

**Why:** Obsidian only renders task syntax as an interactive checkbox in list items — never inside a table cell. Approving a Row therefore meant hand-editing a space into an `x` inside a table cell, which on mobile is precise cursor placement in a horizontally-scrolling row. Approval is the one gesture the confirm-first design requires on *every* Row (see Approve, CONTEXT.md), so making it the most expensive gesture in the system was backwards. Grouping by destination follows from the same reasoning: the dominant real-world case is a large run of Rows sharing one destination (85 of 109 pending Rows were email, mostly discards), and grouping puts them under one heading to be approved together.

Keeping the destination on the Row line is what bounds the change. It leaves Row parsing *line-local* — one line is independently meaningful — so consumers that read Rows without caring about layout (the pending-work nudge, the Dashboard's ticked/pending counts) keep working untouched. A stateful, heading-driven parse would have propagated document structure into every consumer.

Line-locality only pays for itself if the heading is genuinely inert. The first cut of this decision had Execute *read* the heading and refuse the whole Plan where it disagreed with a Row's destination — which made the heading a de facto input, and made re-routing a capture a two-part edit: change the destination *and* hand-move the Row's three-line block under the right heading, creating it if absent. On mobile, moving a three-line block is exactly the class of gesture this decision exists to eliminate. So correcting a Row is a **single in-place edit of its destination**: the Row executes to what it now says, wherever it sits, and `execute.regroup_plan()` — called from both write paths, Execute's marker-stamping write and Triage's — rewrites the groups on the way out, creating headings that are needed and dropping ones left empty. Row blocks move verbatim (tick state, executed marker, numbering, continuation lines); groups keep the order of the existing headings that still hold Rows, then any new destination in the order its first Row appears; Rows keep document order within their group. Re-grouping is driven only by the destination field of recognised Row lines, so capture-derived preview text can never create or name a group.

Re-grouping must be **idempotent**, because both write paths run it on every write whether or not anything else changed — a Plan that is not a fixed point is a Plan that grows every night. That constrains what may be emitted to what can be read back: a Row with a blank destination gets no heading at all (`## ` is not a heading any parser recognises, so emitting one would be re-read as prose and a fresh `## ` emitted below it, forever) and is instead held ungrouped above the groups; prose belonging to no heading is hoisted into the preamble rather than left below the groups, where a second pass would adopt it into the last section. A blank destination is separately treated as a malformed Row, so Execute refuses such a Plan rather than acting on it — it is not actionable, and left alone it would resolve to the Brain root and crash a run part-way through, after earlier Rows had been filed and logged but before the Plan recorded it.

**Trade accepted:** a hand-edit to a *heading* is now silently ineffective — it will be reverted on the next write. That is the price of the heading having no authority at all, and it is the right way round: the heading is the derived thing, the Row line is the fact.

**Rejected:** grouping by route (Pass A/Pass B) — stable and churn-free, but it groups by *how* a Row was classified rather than by what the user is about to approve, so it doesn't enable bulk approval; **heading-authoritative destinations** — still rejected, and regenerating headings is not the same thing: reading the heading (whether to parse from it or merely to check it) makes parsing stateful and pushes document structure into every consumer, whereas writing the heading touches nothing but the writer; refusing a Plan on a heading/destination disagreement (the first cut, reversed above — a document can't contradict you about something you only ever render, and the refusal made correction harder on the device this decision exists to serve); parsing both the old table and the new shape indefinitely (permanently doubles the surface that the shared parser exists to keep from drifting — the open Plans are converted once instead); leaving the table and adding conversational approval instead (cheaper, but doesn't fix the Plan for anyone reading it in Obsidian).
