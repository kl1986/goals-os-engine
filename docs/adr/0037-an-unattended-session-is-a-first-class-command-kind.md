# An unattended session is a first-class Command kind, confined to proposal surfaces

`config/schedules.md` may name an unattended agentic session (`claude -p /<skill>`) as a row's Command, on the same footing as a Python script. Such a session runs with permission prompting disabled and is confined by a PreToolUse hook to writing only *proposal* surfaces — `inbox/triage/`, `inbox/rule-diffs/` and `log/`. Its liveness is tracked in `config/routine-state.md` and a session that has not succeeded within its cadence is reported overdue by Heartbeat. Decided 04/08/2026.

**Why this is recorded rather than just built:** three tickets ([[unattended-claude-session-runner-for-scheduled-llm-routines]], [[triage-has-no-automation-path-at-all-relies-entirely-on]] fix (b), [[activate-rule-learning-close-the-classification-feedback]]) were parked for weeks on the belief that the Scheduler Adapter *could not* fire a Claude session — only a script. That belief was wrong when it was written and is demonstrably wrong now. Three such jobs are live in this Brain and `sync_schedules.py` documents the shape explicitly:

| Label | Command | Timing |
|---|---|---|
| `com.kelvinlee.yt-history` | `claude -p /yt-history --dangerously-skip-permissions` | daily 23:10 |
| `com.kelvinlee.dream` | `claude -p /dream --dangerously-skip-permissions` | Sun 20:07 |
| `com.kelvinlee.chatham-sonia` | `claude -p /chatham-sonia` | Mon–Fri 14:00 |

`yt-history` and `dream` complete unattended and land real work in the Brain. A plist's `ProgramArguments` does not care whether the binary is `python3` or `claude`, so there was never a mechanism to build. The gap was always governance, and leaving it unnamed is what let a false blocker sit in front of the learning loop for a month.

**Skip-permissions is the load-bearing decision, and confinement is what makes it safe.** An unattended session cannot answer a permission prompt; a prompt is therefore a hang, not a gate. The honest options were to run with prompting disabled or to accept that no judgement routine ever runs unattended. We disabled prompting and moved the safety property somewhere it still holds: *what the session can reach*, rather than *what it is asked*.

The three permitted surfaces share a property that makes this sound — nothing written to them takes effect. A Triage Plan is a page of `[ ]` Rows that Execute ignores until they are ticked (ADR-0031). A rule diff is a proposal that `rule_diff_review` will not apply without an explicit decision. An Action Log entry is a record, not an action. So an unattended session can do the whole judgement half of a routine and still change nothing in the Brain until Kelvin approves it. Confirm-first is preserved *structurally* rather than by prompting, which is the only form of it that survives having no human present.

**Enforcement is a PreToolUse hook, not convention.** `adapters/claude-code/` has no `hooks/` directory today, so this ADR creates one. A denial at the tool-call boundary is the only mechanism that actually prevents a write; the alternatives both fail in the direction that matters. A `settings.json` deny-list expresses paths as globs, and a coarse or subtly-wrong glob fails open with no signal. A post-run `git diff` audit detects a violation only after an unattended session with prompting disabled has already made it — which is precisely the window this control exists to close.

**Health is Heartbeat's existing overdue concept, not a new surface.** `com.kelvinlee.chatham-sonia` last succeeded on 10/07/2026 and was still enabled, still scheduled, and silently dead for 25 days — it hit a session limit, then a CAPTCHA, then connection refusals, and nothing anywhere said so. Unattended sessions fail in ways scripts do not: quota exhaustion, mid-response disconnection, a skill whose external dependency changed underneath it. Every one of those exits without a crash the scheduler would notice. Recording last-success against cadence and letting Heartbeat report staleness reuses machinery that already exists and already reaches the Dashboard, rather than inventing a job-health surface that would itself need watching.

**Consequences.** A partially-completed session can leave a half-written Plan; because Plans are regenerated per source and Rows are inert until ticked, the recovery is to re-run, not to repair. Cost becomes a scheduling concern — an unattended session spends tokens on a timer, which a Python job never did. And an unattended session's confinement is only as good as the hook, so the hook is now a piece of safety-critical Engine code and must be tested as such.

**Rejected:** *a purpose-built Engine runner with its own retries and output capture* — reinvents `launchd` plus `claude -p`, both of which already work, and would have shipped a second scheduling concept alongside ADR-0030's; *per-job tool/path allowlists in each `schedules.md` row* — pushes a safety decision into per-row configuration where it will drift, when the surfaces that are safe to write unattended are a property of the system and identical for every such job; *no skip-permissions, halt on prompt* — technically the strictest posture and practically the emptiest, since every judgement routine would halt on its first write.
